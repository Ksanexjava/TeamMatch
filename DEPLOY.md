# Развёртывание Тиммейта с нуля

Пошагово: от подключения к серверу до работающих ботов в MAX и Telegram и мини-приложения.
Рассчитано на Windows на своём компьютере и VPS с Ubuntu.

> Разворачивать нужно на сервере, а не на домашнем компьютере: Telegram должен достучаться
> до мини-приложения из интернета, а у домашнего ПК нет постоянного внешнего адреса.

> **Пока нет домена?** Telegram-бот работает и без него — кнопками в чате, как бот MAX.
> Пропустите шаги 5 и 8, а в `.env` (шаг 7) оставьте только `MAX_BOT_TOKEN`, `TELEGRAM_BOT_TOKEN`,
> `TELEGRAM_BOT_USERNAME` и `COMPOSE_PROFILES=telegram`. Мини-приложение подключите, когда появится домен.

Адрес приложения берём бесплатный — поддомен DuckDNS (`имя.duckdns.org`). Когда появится свой домен,
поменяются только две строки в `.env` (шаг 7).

---

## Что понадобится

- **IP-адрес сервера, логин и пароль** — в личном кабинете хостинга, в разделе вашего сервера
  (обычно «Серверы» → ваш VPS). Логин чаще всего `root`.
- **Архив проекта** — `TeamMatch_miniapp_<дата>.zip` (или доступ к репозиторию).
- **Токен бота MAX** — из старого `.env` на сервере или из кабинета MAX.
- **Аккаунт Telegram** и **аккаунт GitHub или Google** (для входа в DuckDNS).

---

## Шаг 1. Подключиться к серверу

1. На своём компьютере нажмите **Пуск**, наберите **PowerShell** и откройте его.
2. Введите (подставьте свой IP):
   ```bash
   ssh root@123.45.67.89
   ```
3. При первом подключении спросят `Are you sure you want to continue connecting?` — напишите `yes`, Enter.
4. Введите пароль. **Символы при вводе не отображаются** — это нормально, просто наберите и нажмите Enter.
5. Если строка приглашения сменилась на что-то вроде `root@server:~#` — вы на сервере.

Это окно не закрывайте. Для шага 4 понадобится второе окно PowerShell.

---

## Шаг 2. Если бот уже работает на этом сервере — остановить его

Посмотрите, есть ли папка бота:
```bash
ls ~
```
Если в списке есть `TeamMatch`, остановите бота:
```bash
cd ~/TeamMatch && docker compose down && cd ~
```
⚠️ **Не добавляйте `-v`** — этот флаг удалит базу с анкетами. Без него база сохранится.

Переименуйте старую папку в резервную копию — в ней лежит `.env` с токеном MAX:
```bash
mv ~/TeamMatch ~/TeamMatch_old
```

Если бота на сервере не было — пропустите этот шаг.

---

## Шаг 3. Установить Docker (если его нет)

Проверьте:
```bash
docker compose version
```
Пришла версия — переходите к шагу 4. Если `command not found` — установите официальным скриптом:
```bash
curl -fsSL https://get.docker.com | sh
```
И проверьте ещё раз: `docker compose version`.

---

## Шаг 4. Перенести проект на сервер

**Вариант А — архив.**

1. Откройте **второе** окно PowerShell (на своём компьютере, не на сервере) и скопируйте архив
   (подставьте путь к архиву и IP):
   ```bash
   scp "C:\путь\к\TeamMatch_miniapp_2026-11-17.zip" root@123.45.67.89:/root/
   ```
   Пароль снова не отображается при вводе.
2. Вернитесь в окно сервера и распакуйте:
   ```bash
   apt install -y unzip && unzip ~/TeamMatch_miniapp_2026-11-17.zip -d ~
   ```

**Вариант Б — репозиторий** (когда изменения смёржены в `main`):
```bash
git clone https://github.com/Ksanexjava/TeamMatch.git ~/TeamMatch
```

В обоих случаях зайдите в папку:
```bash
cd ~/TeamMatch
```

Папка должна называться именно `TeamMatch`, как у старого бота: по имени папки Docker находит
базу, и старые анкеты подхватятся.

---

## Шаг 5. Бесплатный адрес в DuckDNS

1. Узнайте внешний IP сервера (на сервере):
   ```bash
   curl -4 ifconfig.me
   ```
2. В браузере откройте **duckdns.org**.
3. Вверху страницы нажмите значок **GitHub** или **Google** и войдите.
4. В поле **sub domain** впишите имя, например `teammate-nsu`, нажмите зелёную кнопку **add domain**.
5. Ниже появится строка `teammate-nsu.duckdns.org`. В её поле **current ip** вставьте IP из пункта 1
   и нажмите **update ip**.
6. Через пару минут проверьте на сервере:
   ```bash
   nslookup teammate-nsu.duckdns.org
   ```
   В ответе (`Address:`) должен быть IP сервера.

IP у VPS постоянный, поэтому программа-обновлялка DuckDNS и их токен не нужны.

---

## Шаг 6. Создать Telegram-бота

1. В Telegram найдите **@BotFather** (с синей галочкой), нажмите **Start**.
2. Отправьте `/newbot`.
3. Имя — `Тиммейт`.
4. Username — с окончанием `bot`, например `teammate_nsu_bot`. Занято — попробуйте другое.
5. Придёт сообщение со строкой `Use this token to access the HTTP API:` и токеном вида `123456789:AAH...`.
   Это пароль от бота: **никому его не пересылайте** и не коммитьте в репозиторий.

---

## Шаг 7. Заполнить настройки (`.env`)

1. На сервере, в папке `~/TeamMatch`, создайте файл настроек из шаблона:
   ```bash
   cp .env.example .env
   ```
2. Если была старая папка (шаг 2) — посмотрите токен MAX:
   ```bash
   grep MAX_BOT_TOKEN ~/TeamMatch_old/.env
   ```
3. Откройте редактор:
   ```bash
   nano .env
   ```
4. Стрелками дойдите до нужных строк и впишите значения после `=` — без пробелов и кавычек:
   ```
   MAX_BOT_TOKEN=токен бота MAX
   COMPOSE_PROFILES=telegram,webapp
   TELEGRAM_BOT_TOKEN=токен от BotFather
   TELEGRAM_BOT_USERNAME=teammate_nsu_bot
   WEBAPP_DOMAIN=teammate-nsu.duckdns.org
   WEBAPP_URL=https://teammate-nsu.duckdns.org
   WEBAPP_DEV_AUTH=0
   ```
   Остальные строки не трогайте. ⚠️ `WEBAPP_DEV_AUTH` на сервере — всегда `0`.
5. Сохранить: **Ctrl+O**, затем **Enter**. Выйти: **Ctrl+X**.

---

## Шаг 8. Открыть порты 80 и 443

1. Проверьте, что порты свободны:
   ```bash
   ss -ltnp | grep -E ':80 |:443 '
   ```
   Пусто — хорошо. Если видите `nginx` или `apache` — остановите их, иначе HTTPS не заработает.
2. Откройте порты в файрволе сервера:
   ```bash
   ufw allow 80,443/tcp
   ```
3. Если у хостинга в личном кабинете есть раздел **«Файрвол»** или **«Сетевые правила»** —
   откройте входящие TCP 80 и 443 и там.

---

## Шаг 9. Запуск

```bash
docker compose up --build -d
```
Первый запуск — 2–5 минут: скачиваются образы и собирается проект. Проверьте:
```bash
docker compose ps
```
Должно быть шесть сервисов со статусом `running` / `Up`: `bot`, `tgbot`, `webapp`, `caddy`, `postgres`, `redis`.

---

## Шаг 10. Проверка

1. **Сертификат** — должна быть строка `certificate obtained successfully`:
   ```bash
   docker compose logs caddy | grep -i "certificate obtained"
   ```
2. **Telegram-бот** — должна быть строка «Telegram-бот запущен: @имя_бота»:
   ```bash
   docker compose logs tgbot | tail -20
   ```
3. **В браузере** откройте `https://teammate-nsu.duckdns.org` — экран «Открой в мессенджере», замок у адреса.
4. **В Telegram** найдите своего бота → **Start** → кнопка **«Открыть Тиммейт»**. Заполните анкету,
   лайкните любую — придёт мэтч (тестовые анкеты лайкают в ответ).
5. **Бот MAX** работает как раньше — напишите ему `/start`. Его кнопки «Согласие» и «Политика»
   теперь ведут на страницы документов.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Нет сертификата | Закрыт порт 80 или в DuckDNS не тот IP — шаги 5 и 8, затем `docker compose restart caddy` |
| Бот в Telegram молчит | Видит ли сервер Telegram: `curl https://api.telegram.org/bot<ТОКЕН>/getMe`. Нет ответа — раздел «Хостинг не пускает к Telegram» ниже |
| В логах `Conflict: terminated by other getUpdates` | Этот же токен запущен где-то ещё (например, у кого-то локально) |
| В логах `can't use getUpdates while webhook is active` | Один раз выполнить `curl https://api.telegram.org/bot<ТОКЕН>/deleteWebhook` |
| Приложение пишет «Подпись initData не сошлась» | В `.env` токен не того бота |
| Бот MAX перестал отвечать | `MAX_BOT_TOKEN` в `.env` и `docker compose logs bot` |

## Хостинг не пускает к Telegram

Симптом: контейнер `tgbot` поднимается и через несколько секунд падает с
`TelegramNetworkError: Request timeout error`. Это не ошибка бота — исходящие
соединения к Telegram с сервера не проходят.

### Как убедиться, что дело в сети

```bash
curl -v -m 10 https://api.telegram.org/ 2>&1 | grep -E "Trying|Connected|timed out"
```

Строки `Connected to` нет, только `Trying` и таймаут — пакеты до Telegram
не доходят. Проверьте, что дело именно в Telegram, а не в интернете вообще:

```bash
curl -sS -m 8 -o /dev/null -w "%{http_code}\n" https://api.github.com/
```

Если тут `200`, значит сеть у сервера есть и режут конкретно Telegram. Своего
firewall на сервере при этом может и не быть — проверьте `iptables -S OUTPUT`.

### Что делать

**Сначала — письмо в поддержку хостинга.** Бесплатно и иногда решает вопрос.
Просите не «разблокировать Telegram», а снять фильтрацию исходящего трафика
к диапазонам `149.154.160.0/20` и `91.108.4.0/22`, и приложите вывод `curl -v`.

**Если отказали — свой ретранслятор.** Бот ходит не в `api.telegram.org`, а на
бесплатный Cloudflare Worker, который пересылает запросы дальше. Скрипт лежит
в [tools/telegram-relay-worker.js](tools/telegram-relay-worker.js), там же порядок установки.
Коротко: завести бесплатный аккаунт Cloudflare, создать Worker, вставить скрипт,
заменить в нём `SECRET` на случайную строку (`openssl rand -hex 16`), нажать Deploy.
Затем в `.env`:

```
TELEGRAM_API_BASE=https://имя.поддомен.workers.dev/<SECRET>
```

и `docker compose up -d --build tgbot`. В логах появится строка
`Bot API через ретранслятор, хост ...`, а за ней обычное `Telegram-бот запущен`.

Чем за это платим: TLS обрывается на стороне Cloudflare, то есть платформа видит
переписку и токен бота. Для пилота это приемлемо, для работы с персональными
данными всерьёз — нет. Правильное решение там одно: хостинг, который не режет
Telegram. Переезд недорогой, весь проект в Docker Compose, нужна только смена
A-записи домена.

Ретранслятор нужен и боту, и уведомлениям: `TELEGRAM_API_BASE` читают все сервисы,
никаких других правок не требуется. Чтобы вернуться к прямому доступу, очистите
переменную.

## Мини-приложение не открывается из-под VPN

Симптом: мессенджер работает, а мини-приложение не грузится. Без VPN всё в
порядке. Причина — сервер стоит на российском IP, и трафик из-за границы до
него не доходит: либо выходной узел VPN туда не маршрутизируется, либо хостинг
режет входящие соединения из таких диапазонов.

**Быстрая проверка, чья это беда.** Открыть с включённым VPN `ya.ru`. Грузится
— значит до России трафик доходит, и дело в конкретном хостинге. Не грузится —
VPN рубит всю страну, и переезд ничего не изменит.

**Обход для Telegram.** Перед приложением стоит ретранслятор на бесплатном
Cloudflare Worker — он уже развёрнут под именем `teammate-app`, исходник в
[tools/webapp-proxy-worker.js](tools/webapp-proxy-worker.js). Чтобы включить,
достаточно прописать его адрес в `.env`:

```
TELEGRAM_WEBAPP_URL=https://teammate-app.michael-biysk.workers.dev
```

и `docker compose up -d --build`. Тот же адрес прописывается в @BotFather →
Bot Settings → Menu Button. MAX остаётся на прямом домене: там мини-приложение
прошло модерацию платформы, и смена адреса потребует её заново.

**Чем за это платим и когда убрать.** TLS обрывается на стороне Cloudflare,
то есть платформа видит содержимое запросов. Пока в базе только тестовые
анкеты, это приемлемо. **До пилота с живыми людьми ретранслятор нужно убрать**
— очистить `TELEGRAM_WEBAPP_URL` и перенести сервис на хостинг, доступный
напрямую. Тот же переезд уберёт и ретранслятор Bot API (см. раздел выше).

## На каждый день

Все команды — из папки `~/TeamMatch`.

| Задача | Команда |
|---|---|
| Логи Telegram-бота | `docker compose logs -f tgbot` |
| Логи мини-приложения | `docker compose logs -f webapp` |
| Логи бота MAX | `docker compose logs -f bot` |
| Остановить всё | `docker compose down` |
| Применить правки `.env` | `docker compose down && docker compose up -d` (`restart` не перечитывает `.env`) |
| Обновить код из репозитория | `git pull && docker compose up --build -d` |

⚠️ `docker compose down -v` удаляет базу с анкетами — без крайней нужды не использовать.

Когда всё заработает, старую папку `~/TeamMatch_old` можно удалить.

## Подключить мини-приложение в MAX (позже)

Доступно после верификации профиля (юрлицо, ИП или самозанятый) на
[business.max.ru](https://business.max.ru/self): **Чат-боты** → ⋮ у бота → **Настройки** →
вставить `WEBAPP_URL` в поле ссылки на мини-приложение → **Сохранить**. Затем модерация.
Сервер для этого менять не нужно — мини-приложение одно на оба мессенджера.
